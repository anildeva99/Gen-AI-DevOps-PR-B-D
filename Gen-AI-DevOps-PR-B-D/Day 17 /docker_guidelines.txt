# 🐳 Dockerfile Best Practices for Production-Ready Containers

1. ✅ Use official base images with explicit tags:
   - Example: `FROM python:3.9-slim` instead of `FROM python:latest`.

2. 📁 Set a working directory:
   - Use `WORKDIR /app` to organize files and simplify commands.

3. 📦 Copy only what you need:
   - Copy `requirements.txt` first, install dependencies, then copy the rest of the source code.
   - This improves build caching and reduces image size.

4. 🔐 Use a non-root user:
   - Avoid running as root inside containers. Add:
     ```
     RUN useradd -m appuser
     USER appuser
     ```

5. 🚀 Multi-stage builds:
   - Use builder and runtime stages to reduce final image size.
   - Example:
     ```
     FROM python:3.9 AS builder
     WORKDIR /app
     COPY requirements.txt .
     RUN pip install --user -r requirements.txt

     FROM python:3.9-slim
     WORKDIR /app
     COPY --from=builder /root/.local /root/.local
     COPY . .
     ENV PATH=/root/.local/bin:$PATH
     CMD ["python", "app.py"]
     ```

6. 📂 Use `.dockerignore`:
   - Exclude unnecessary files like `.git/`, `__pycache__/`, `.env`, `tests/`.

7. ⚙️ Environment variables:
   - Use `ENV` instructions for configuration defaults instead of hardcoding values.

8. 🧹 Clean up layers:
   - Combine related commands with `&&` and clean cache after installations.

9. 🛡️ Security:
   - Scan images regularly with tools like Trivy or Snyk.
   - Avoid hardcoding secrets in the image. Use environment variables or external secret stores.

10. 📊 Logging & Observability:
   - Ensure the container writes logs to `stdout` and `stderr` for integration with container orchestration logging.

11. 🔄 Health Checks:
   - Use Kubernetes readiness/liveness probes to monitor the container’s health.
